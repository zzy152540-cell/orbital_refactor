# V15 系统级验收基线

## 1. 目的与边界

系统级验收用于确认已经实现的轨道、量测、滤波、通信、拓扑和CANN边界能够通过统一入口协同运行。它不以单次精度提升证明算法优越性，也不替代各专项Monte Carlo和统计验收。

学习模块不参与当前smoke验收。GNN、PPO或CANN均不得替代原有滤波器；CANN关闭或正常直通时必须保持原路径结果。

## 2. Smoke场景

| 场景 | 覆盖内容 | 当前硬门槛 |
|---|---|---|
| 单星三模态+CANN边界 | 雷达、红外、光学及可选预处理 | 输出有限；正常无故障时基线与CANN路径可比较 |
| 三星多模态可见性 | 本地观测、连续/可见性受限、传播/精确回放 | 三传感器接入；无消息拒绝；协方差PSD |
| 五星动态重同步 | 环形拓扑、链路失活与恢复、谱系更新 | 至少一次重同步；无协议拒绝；联合协方差PSD |
| 十星动态重同步 | 中等规模环形拓扑、链路失活与恢复 | 至少一次重同步；无协议拒绝；联合协方差PSD |
| Walker-20分布式滤波 | Python Walker真值、三模态、精确回放 | 20节点；无消息拒绝；协方差PSD；指标有限 |

运行命令：

```bash
python -m experiments.run_v15_system_acceptance \
  --profile smoke \
  --output results/v15_system_acceptance_smoke.json
```

也可以通过`--cases`只运行一个或多个指定场景。失败记录不会被隐藏，命令返回非零退出码，JSON中保留具体失败原因。入口同时输出CSV，并记录每项墙钟运行时间和Python分配峰值；峰值不包含NumPy底层库可能绕过Python分配器的全部内存，因此只作为可重复的工程代理量。

## 3. 首轮结果

首轮五项smoke全部通过：

- 单星正常三模态基线与CANN路径的位置RMSE均为51.9668 m，差值为0；
- 三星多模态四个对照的最大平均位置RMSE为3.3595 m，消息拒绝和PSD失败均为0；
- 五星动态场景平均位置RMSE为1.7285 m，触发2次重同步，协议拒绝为0，最小联合协方差特征值约为`1.044e-4`；
- 十星动态场景平均位置RMSE为2.7957 m，触发2次重同步，协议拒绝为0，最小联合协方差特征值约为`1.044e-4`；
- Walker-20短时smoke位置RMSE为3.3575 m，消息接受率为1，消息拒绝和PSD失败均为0，最小联合特征值约为`1.941e-4`。

在当前机器和短时smoke配置下，各场景墙钟时间依次约为2.465、0.954、1.006、2.021和3.497 s；记录到的Python分配峰值依次约为2.08、1.53、2.18、4.16和10.58 MiB。这组数值只作为后续回归比较的首个工程快照，不作为实时性或总内存结论。

这些结果只证明短时工程流程健康，不代表长时精度、跨种子统计性能、实时性或最坏条件已经通过正式验收。

## 4. 尚未完成的Formal层

后续formal配置应单独增加：

1. 每类场景的多随机种子和置信区间；
2. 5/10/20星一致的正常、失锚、通信退化和动态拓扑矩阵；
3. RMSE、NEES、NIS、拒绝率、恢复时间、消息、回放、重同步、内存和运行时间阈值；
4. CANN与同信息传统鲁棒预处理器的公平对照；
5. 长时Walker测试和服务器级低频验收；
6. 设计冻结后的一次性封存条件验证。

只有formal层通过后，才能声称传统状态估计和可选sidecar形成经过系统验证的完整闭环。

所有组的最小联合协方差特征值均为正，失联恢复组均完成显式重同步，随机丢包和固定时延组均无协议拒绝。实现补充了活动链路在`history_unavailable`、`resync_required`或`event_bundle_endpoint_mismatch`后的自动新谱系重同步。协议级重同步采用发送端当前状态—协方差快照，并以`zero_cross`显式丢弃已经无法证明的交叉协方差，避免将接收端已经漂移的邻星估计错误地声明为共同基线。

停止等待通信下，历史钉住时长还必须覆盖往返时延并留出至少一个处理历元；当前Formal配置采用不小于`4*dt`的窗口。短于该约束的窗口仍会安全触发重同步，而不是接受不兼容协方差。由于每组只有3个种子且时长仅20 s，表中的95%半宽仍只能用于检查统计管线，不能作为正式置信结论。下一步可加入多节点失锚、多链路变化和更长持续时间。

失锚场景在5–15 s之间抑制`sat_01`的5个绝对位置量测，星间三模态量测保持启用。除舰队平均RMSE外，输出中新增目标节点RMSE：5星场景较正常参考变化约−0.10 m，10星增加约0.16 m，20星增加约0.48 m。5星负差值应视为三种子短时波动，不能解释为失锚改善性能。下一步应增加失锚期和恢复期的目标节点分段指标，然后测试多节点同时失锚。

采用同种子、同规模、同评价窗口的匹配参考后，失锚窗口内目标节点RMSE增量在5/10/20星下分别约为−0.02、+0.31和+0.90 m；恢复窗口内分别约为−0.61、+0.31和+0.51 m。负值仍属于当前三种子短时波动，不构成性能改善证据。10星和20星在恢复窗口仍保留正增量，后续长时验收需要定义“重新获得绝对导航后回到正常参考误差带”的恢复时间。

双节点同时失锚采用`sat_01`和`sat_02`，其余节点保持绝对导航。与相同双节点评价口径的正常参考相比，失锚期两节点平均RMSE增量在5/10/20星下分别约为+0.19、+0.67和+0.52 m；恢复期分别约为−0.14、+0.62和+0.28 m。结果没有随节点总数单调改善，说明协同支撑能力还取决于失锚节点的局部几何与拓扑位置，不能只用剩余节点数量解释。

组合场景同时施加双节点失锚、20%随机丢包和2 s固定时延。历史钉住窗口提高到不小于`6*dt`，以覆盖丢包造成的额外确认等待。9项组合测试均无协议拒绝。相对双节点评价正常参考，失锚期受影响节点平均RMSE增量在5/10/20星下约为+0.33、+0.83和+0.62 m；相对仅双节点失锚又增加约0.14、0.16和0.10 m，表明通信退化带来了可测但当前仍受控的附加损失。
