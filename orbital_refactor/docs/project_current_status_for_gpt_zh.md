# 星群协同状态估计项目现状说明（供 GPT 阅读）

> 更新时间：2026-09-02  
> 当前开发分支：`feature/v15-cann-feedback-validation`  
> 文档用途：向新的 GPT 会话完整交代项目目标、现行实现、验证证据、CANN 分支进度与后续计划，减少脱离代码现状的重复讨论。

## 0. 阅读与讨论约束

请在后续讨论中遵守以下边界：

1. **GNN、RL 和 CANN 都不替代现有状态估计器。**现有 EKF、Schmidt、联邦/CI 融合链路是可信基线。
2. **CI 只融合“同一物理状态”的多个估计结果**，不能直接把不同卫星的物理状态相互融合。
3. 集中式 Fleet EKF 仅作为小规模验证与性能上界参考，不是最终分布式架构。
4. 必须区分“已实现”“实验性实现”和“规划中”，不能把单一场景或单一随机种子的结果写成普遍结论。
5. 固定拓扑、仅距离量测或理想通信下的实验，不能代表完整的多模态、可见性约束、动态通信星群算法已经验证完毕。
6. CANN 应保持在滤波器边界之外：它可以形成量测建议、异常抑制或辅助状态，但不得暗中改变原滤波状态、协方差传播和 CI 数学定义。

---

## 1. 项目目标

本项目研究面向卫星星群的分布式协同状态估计与智能拓扑决策。总体目标是：

- 每颗卫星维护自身绝对状态估计；
- 利用雷达、传统光学、红外等多模态星间相对量测；
- 在视线、量程、姿态、通信时延、丢包和拓扑变化约束下交换状态或观测信息；
- 通过协方差一致的分布式估计机制避免信息重复利用和过度自信；
- 在可信确定性拓扑策略之上，引入 GNN/RL 学习节点、链路或资源调度策略；
- 作为类脑扩展，探索 CANN 对周期角度跟踪、异常量测抑制和短时动态记忆的价值。

项目当前概念阶段为 **V15**。V14 主要完成估计、通信一致性、多模态与 Walker 星座验证基础；V15 重点转向图观测、确定性拓扑策略、GNN 初始化和安全约束 RL。当前另建功能分支开展 CANN 可行性验证。

## 2. 总体技术架构

```text
轨道/Walker 真值与场景配置
            ↓
多模态量测生成 + 可见性判定 + 故障/噪声注入
            ↓
（可选）CANN 量测侧适配器或被动辅助状态
            ↓
原有局部 EKF / 多邻居 Schmidt 更新
            ↓
同一目标的联邦-CI融合 + 分布式通信/协方差安全机制
            ↓
状态、协方差、NIS/NEES/RMSE、通信与拓扑诊断
            ↑
GraphObservation → 确定性策略或 GNN/RL 拓扑策略
```

三条研究线的边界如下：

| 研究线 | 职责 | 不负责 |
|---|---|---|
| 状态估计主线 | 动力学传播、量测更新、Schmidt、CI、一致性诊断 | 不依赖学习算法才能正常工作 |
| GNN/RL | 根据合法候选边和当前图状态选择拓扑/通信动作 | 不直接输出卫星状态，不替代滤波器 |
| CANN | 对量测时序形成可选建议、异常抑制或连续吸引子辅助状态 | 不改写 EKF/CI 核心数学，不在无量测时伪造观测 |

## 3. 状态估计主线的现状

### 3.1 动力学与场景

已实现：

- 二体/J2 轨道动力学与 RK4 数值传播；
- 单星、差分编队和 Python 生成的 Walker 星座真值；
- 5、10、20 星等不同规模实验入口；
- ECI 坐标系下的绝对位置导航与星间相对观测；
- 地球遮挡、距离、视场和姿态等可见性约束，以及可见性状态的时间稳定处理。

当前 Walker 场景能够支持较长时间仿真和动态图结构，但现有训练样本中的轨道构型与初值多样性仍不足，后续需加强轨道面、相位、节点数、噪声、故障和通信条件的随机化。

### 3.2 状态变量与量测变量

典型单星状态为 ECI 坐标系下的位置和速度：

```text
x = [rx, ry, rz, vx, vy, vz]^T
```

多星实现中，每颗卫星保留自身局部状态；多邻居 Schmidt 更新还会在联合/考虑状态中维护邻星状态及必要的交叉协方差，但不会把不同卫星的状态视为同一状态做 CI。

已接入的量测语义包括：

- `RANGE`：星间距离；
- `RANGE_RATE`：星间距离率；
- `AZ_EL`：方位角/俯仰角；
- `RADAR`：当前采用距离与距离率组合；
- `INFRARED`：角度量测；
- `OPTICAL`：像面/角度语义，并具有相应观测模型与 Jacobian；
- 绝对位置导航：作为本星绝对锚点进入局部更新。

单星和多星已在量测类型、可见性入口和诊断字段上做过对齐。多星默认采用“观测者本地使用”：例如 A 观测 B 的量测用于更新 A 的局部估计；量测向两端共享只作为可选对照，不是当前默认架构。

### 3.3 滤波与融合

已实现：

- 单星多模态局部滤波与联邦-CI输出；
- 多星分布式局部滤波；
- 多邻居 Schmidt 更新：本星为活动状态，邻星为考虑状态；
- 联合协方差、交叉协方差和重复信息控制；
- NIS 诊断、软协方差膨胀、极端量测硬拒绝；
- RMSE、NEES、一致性、拒绝原因和运行状态等指标。

不同路径的门控算法历史上仍有少量兼容差异：单星旧基线偏固定倍率膨胀/拒绝，多星路径支持按 NIS 比例膨胀、重算后再极端门控。诊断语义已经统一，算法完全统一仍可作为后续维护项，但不应在 CANN 实验中顺便改变滤波基线。

### 3.4 通信与协方差一致性

V14 一致性迭代已经建立：

- 带来源/谱系信息的消息；
- 精确协方差传输与兼容性判断；
- 多邻居 Schmidt 回放；
- 时延、丢包、ACK、乱序消息处理；
- 有界历史窗口、历史钉住、内存/事件上限与显式重新同步；
- 拓扑版本、有效/失联邻星、最后接收时间、连续丢包、拒绝原因和资源峰值等诊断。

这些机制是分布式一致性的支撑层，不等同于完整多模态算法已经在所有星座和通信条件下完成统计验证。

## 4. 拓扑、GNN 与 RL 的现状

### 4.1 统一接口与确定性基线

已建立：

- `GraphObservation`：节点、边、全局与合法动作所需的图观测；
- `TopologyAction`：`keep / add / remove / swap` 等动作；
- `TopologyPolicy`：确定性策略与学习策略共用接口；
- 合法动作掩码、连通性和工程约束；
- `LowChurnConnectedTreePolicy` 等确定性低切换基线；
- 反事实 rollout、条件 Monte Carlo 与拓扑/滤波/通信联合指标。

确定性策略的作用不是宣称已经找到全局最优拓扑，而是提供：可信运行基线、动作合法性参照、数据采集策略和 RL 安全回退。

### 4.2 GNN 基线

当前 GNN 被定义为 RL 的图编码器和合理初始化，不要求单独完成精确全局寻优。现有基线大致采用：

- 共享参数的边感知消息传递网络；
- 残差结构、约 2 层 MPNN、隐藏维度约 64；
- 节点聚合和 mean/max 图级池化；
- 分层动作头：先判定动作类型，再在该类型的合法候选中选择具体边；
- 回归、排序、listwise 或分层分类等预训练试验；
- 严格按随机种子划分训练/验证，避免同轨迹快照泄漏；
- 推理阶段不允许使用真值、未来信息或反事实标签。

已有小规模离线结果说明网络能够学习部分动作排序结构，但数据规模和分布覆盖仍不足，不能把训练准确率直接等同于闭环拓扑收益。

### 4.3 RL 基线

当前路线为带合法动作掩码的分层 PPO：

- Actor 可由 GNN 预训练权重初始化；
- Critic 单独训练，可用有限时域 Monte Carlo 目标预拟合；
- 使用 GAE、PPO clipped objective 和分离的 Actor/Critic 编码器；
- 奖励以归一化估计误差改善为核心，同时考虑通信、时延、拓扑切换和风险成本；
- 设置确定性参考策略、LCB/优势门控与非法动作 `keep` 回退；
- 目标是跨节点规模和场景分布学习局部共享策略，而不是为每个固定星数训练完全独立的控制器。

当前主要发现：

- Walker-20 某些确定性/学习策略可获得小幅 RMSE 改善，但会增加消息、回放、切换和重同步成本；
- 早期策略曾出现动作塌缩，如偏向 `keep` 或 `add`；
- 在同质通信分布上训练的检查点对独立链路分布泛化较差；
- Critic 预拟合能明显提高值函数解释方差，但不必然立刻改变确定性动作与最终 RMSE；
- 目前尚未证明 PPO 在所有条件上相对确定性参考策略非退化。

因此，GNN/RL 仍是**研究原型**，不是替换当前确定性拓扑策略的正式默认实现。

## 5. CANN 扩展的定位与实现

### 5.1 设计边界

CANN 当前位于量测侧或作为被动辅助状态：

```text
雷达量测 →（可选：双 Line CANN / 异常建议）→ 原雷达局部 EKF ─┐
光学量测 →（可选：Plane CANN / 异常建议） → 原光学局部 EKF ─┼→ 原联邦-CI
红外量测 →（可选：Ring-Line CANN / 异常建议）→ 原红外局部 EKF ─┘
```

强制约束：

- 正常量测应尽可能原样通过；
- CANN 只输出标准化的 `CANNMeasurementProposal`，由既有入口决定是否更新；
- 原始量测无效或不可见时，CANN 不得产生“虚拟有效量测”；
- CANN 不改变 EKF 的状态定义、协方差传播、Schmidt 或 CI；
- 所有 CANN 功能均可关闭，关闭后应回到原有结果。

### 5.2 已实现的 CANN 形式

目前已实现或试验：

- 一维周期 **Ring CANN**：FFT 卷积、活动包解码、外部线索与正/负速度驱动；
- 一维有界 **Line CANN**：适合非周期连续变量；
- **耦合 Ring-Line CANN**：适合方位角与俯仰角组合；
- 可分离二维 **Plane CANN**：适合光学像面坐标；
- 雷达：两个 Line CANN 分别对应距离和距离率；
- 红外：Ring-Line 处理周期方位与有界俯仰；
- 光学：Plane CANN 处理归一化像面坐标；
- 轨道相位被动 sidecar：可附着于单星模块，但不反馈改变主滤波器。

当前工程实现是“基于连续吸引子原理的离散复现”，而不是宣称逐项严格复现某一篇连续时间神经动力学论文。

### 5.3 已得到的主要结果

1. **正常无故障场景**：有无 CANN 的滤波曲线应基本重合。这符合“正常量测直通、主滤波不变”的设计目标。
2. **完全量测缺失**：CANN 不填补无观测区间，因此不能解决纯失联/纯不可见问题。有无 CANN 区别很小是合理结果，而非实现失败。
3. **人工脉冲异常**：在当前三模态单星种子 0 场景中，CANN 量测侧异常处理显著降低了异常后的误差：
   - 位置 RMSE：约 `946.23 m → 41.34 m`；
   - 恢复段位置误差：约 `505.65 m → 9.24 m`；
   - 速度 RMSE：约 `5.649 m/s → 0.176 m/s`。
4. **错峰无故障缺失**：红外、雷达、光学分别设置缺失窗口时，CANN 与原基线总体接近；它没有凭空恢复缺失信息。
5. **缺失恢复后立即发生异常**曾暴露严重缺陷：旧逻辑把首个恢复样本直接作为重锚点，导致异常污染 CANN 内部状态并产生级联替代。

### 5.4 最新修复：恢复确认状态机

最新提交 `67d45f1` 将恢复逻辑改为 fail-closed 的“两样本确认”：

- 长间隔后的第一个返回量测只作为候选，隔离且不送入 EKF；
- 第二个返回量测必须与候选在物理连续性上相容，才能确认并重锚定；
- 不相容时滚动候选，直到出现连续相容样本；
- 红外采用圆周角连续性；
- 雷达检查距离增量与距离率的一致性；
- 光学检查像面连续性。

在同一恢复故障场景中，修复后的结果为：

- CANN 位置 RMSE：约 `15.416 m`；
- 恢复段位置误差：约 `5.727 m`；
- 速度 RMSE：约 `0.08794 m/s`；
- 原先出现的雷达级联替代由 349 次降为 0。

近期 CANN 完整测试共 69 项通过，定向恢复逻辑测试 19 项通过。

### 5.5 CANN 结论的适用范围

当前只能得出：CANN 侧车及其异常/恢复逻辑在设定的合成脉冲故障中具备潜力，并能在关闭时保持主滤波基线。

尚不能得出：

- CANN 在所有噪声、故障和轨道场景中都优于传统方法；
- 性能提升完全来自连续吸引子动力学，而不是门控、确认或替代规则；
- 单星单种子结果可直接推广到多星；
- CANN 能解决完全缺失信息问题。

当前恢复故障正式结果主要来自 seed 0、固定缺失窗口和有限的相反方向脉冲组合，阈值也仍是工程设定，尚未充分统计标定。

## 6. 稳定接口与输出

### 6.1 单星入口

典型调用入口：

```python
module = StateAwarenessModule()
output = module.run(module_input)
history = module.run_history(module_input)
```

核心输入对象包括：

- 初始状态与协方差；
- 传感器量测序列；
- 场景、滤波、通信、可见性和可选 CANN 配置；
- 必要的节点报告或邻星信息。

标准观测对象包含：

```text
timestamp, observer_id, target_id, modality/source_type,
measurement, covariance, confidence, frame, valid_flag, metadata
```

### 6.2 多星入口与输出

多星协同实验通过 cooperative pipeline/orchestrator 运行，支持集中式验证和分布式模式。标准输出覆盖：

- 状态与协方差历史；
- 融合状态和异常事件；
- NIS、NEES、RMSE 与拒绝统计；
- 当前拓扑、有效/失联节点、链路状态；
- 消息、回放、重同步、历史窗口和资源峰值；
- 可导出的 CSV、NPZ 和 JSON 运行包。

- Ring、Line、Ring-Line、Plane CANN 原型及三模态量测适配；
- CANN 缺失恢复后的候选确认修复和回归测试。

### 8.2 仍属实验性、尚未成为正式默认

- GNN 学习拓扑相对确定性策略的稳定收益；
- PPO 在不同节点数和通信分布下的非退化保证；
- CANN 三模态异常处理的跨种子、跨故障统计结论；
- CANN 从单星量测侧扩展到多星场景的收益与资源评估；

- GNN/RL 的跨规模泛化和独立链路分布训练；

- 运行时间、内存、消息和能源代理成本的统一验收；
- 必要时继续统一单星/多星门控实现，但须单独变更和回归。

## 9. 当前推荐的后续开发顺序

### 阶段 A：关闭 CANN 单星量测侧可行性验证

1. 将恢复故障实验扩展到多个随机种子；
2. 增加同方向连续异常、缓慢偏置、漂移、噪声渐增、间歇丢测等场景；
3. 与不含 CANN 的传统鲁棒方法公平比较，例如创新门控、Hampel/中值处理或 PLL 类角度跟踪；
4. 同时统计 RMSE、恢复时间、NIS/NEES、误拒绝、漏检、计算时间和内存；
5. 判断收益来自 CANN 动力学还是外围门控逻辑；
6. 通过后再决定是否接入多星，未通过则保留为研究性基线。

### 阶段 B：回到 V15 智能拓扑主线

1. 扩大轨道、节点数、可见性、链路和故障条件随机化；
2. 以 5/10/20 星和未见随机种子开展分层验证；
3. 强化 `undirected_independent` 等异质链路分布训练；
4. 完善奖励分项、动作 advantage/Q 分布和各规模 baseline RMSE 审计；
5. 继续 Critic 预拟合与 masked PPO，但保留确定性参考策略、优势门控和 `keep` 回退；
6. 用条件非退化、最差情况、通信成本和拓扑切换率决定是否提升为正式策略。

### 阶段 C：系统级综合验证

在 A、B 分别通过后，再测试 CANN、动态拓扑和分布式多模态滤波的组合。组合实验必须先证明各模块单独有效，再检查模块间耦合，避免把多个研究变量一次性混在同一结论中。

## 11. 当前一句话总结

项目已经形成可运行的多模态分布式状态估计、协方差一致通信、确定性拓扑与 GNN/RL 试验框架；当前 CANN 分支已完成三模态量测侧原型和关键的缺失恢复防污染修复，但 GNN/RL 的跨分布稳定收益与 CANN 的统计性优势都仍需通过更丰富、公平、分阶段的验证后才能进入正式架构。
