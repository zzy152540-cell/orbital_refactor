## 2. 结论摘要

当前代码已经具备30星双方场景、无标签三模态前端、自主初始定轨、多目标关联、航迹生命周期、固定拓扑协同、增量CANN和结果导出的完整开发链路，但还不能宣称十项外协指标全部通过。

当前最重要的结论如下：

- 30星规模、三类状态输出、三模态输入和15条目标航迹已经打通；
- 统一光电径向故障接管配置已经完成 120 s、seeds 0--4 正式入口复验：光学、红外、雷达缺失的池化位置RMSE增幅分别为0.48%、0.10%和3.67%，95%区间分别为[0.22%，0.67%]、[0.04%，0.21%]和[−1.72%，6.26%]，覆盖有效性闸门通过且三类均满足15%门限；
- 雷达无任何径向替代信息时增幅48.13%的旧结果保留为消融证据，不代表当前冻结验收配置；
- 独立径向备份影子候选以每观测节点0.2 m距离、0.0125 m/s距离率为起始信息规格，在同一联合融合+CANN架构下把雷达缺失池化位置RMSE增幅降至2.33%，95%区间[1.85%，6.40%]，五个seed均低于15%。该结果证明信息方向有效，但结果文件明确标记`physicalValidation=false`，在映射到真实传感器之前不得把R06改判为正式满足；
- 径向备份边界扫描进一步将稳定规格放宽到每观测节点1 m距离和0.0125 m/s距离率：120 s五seed池化增幅3.36%，95%区间[2.38%，5.44%]，逐seed均通过。距离率放宽到0.025 m/s时池化增幅8.27%且区间上界13.21%，但seed 2为15.51%且速度辅助指标失败，只能视为边界规格；仅1 m距离、无距离率时长时池化增幅38.75%，明确失败；
- 3/15我方节点失效已完成空间分散、拓扑相邻、高可见性贡献和逐seed随机四类冻结组合。存活节点共识位置平均误差的五seed均值增幅依次为−0.78%、−4.08%、−0.15%和−0.32%，四类覆盖闸门均通过，属于L2开发预扫通过，不等于正式验收完成；
- P05和P07已经完成120 s、seeds 0--4的可审计跨运行臂开发预扫。P05四臂消融表明：原联邦-CI架构内CANN增量为0%，联合融合本身池化RMSE改善83.03%，联合架构内CANN额外增量仅0.39%且seed级95%区间跨0，联合融合+CANN总改善83.10%。组合候选达到L2数值门限，但主要收益必须归因于融合架构。调整后P07使用联合量测算法的独立/协同同算法配对，池化平均误差改善18.90%、RMSE改善14.41%，逐seed RMSE改善12.36%--17.10%，达到L2数值门限但尚非正式通过；
- 最新120 s、seed 0本机直接基准的算法历元平均耗时约152.40 ms、P95约168.06 ms，属于单独的整历元实时性风险；P09专用跨进程UDP目标报告链路已经完成120帧预扫并低于100 ms；
- 新30星场景的完整可视化回归尚未完成；
- 当前测试套件可收集1137项测试；最近一次与本轮实时关联优化直接相关的回归为82项全部通过，但本轮没有重新执行全部1137项测试。

## 3. 测试状态分级

后续报告统一使用以下状态，禁止只写“通过”而不说明证据级别：

| 状态 | 含义 |
|---|---|
| 已实现 | 接口和执行路径存在，至少有自动化测试覆盖，但未必完成指标测试 |
| 开发预扫通过 | 小规模、短时或少量随机种子满足门限，只能用于开发决策 |
| 正式通过 | 冻结代码和配置后，完成正式时长、随机种子、配对输入、覆盖检查和置信区间统计 |
| 未满足 | 当前有效证据超过规定门限 |
| 待判定 | 缺少公平基线、统一口径、有效结果或正式测试 |
| 旧结果作废 | 结果受到已修复缺陷、不同口径或不完整覆盖影响，不再用于验收 |

### 4.4 当前结果不能支持的结论

以下说法目前均不成立：

- “所有外协指标已经通过”；
- “CANN在正常或纯模态缺失场景显著提高位置精度”；
- “低于1 s节拍等价于满足100 ms同步延迟”；
- “旧三种子基准矩阵可以继续用于8%或6%指标”；
- “集中收集多站LOS量测的验证实现已经等同于最终分布式实现”；
- “单个seed或单个目标的改善可以代表全群正式结论”。

### 4.6 历史“达到门限”结论的口径还原

旧V1指标编号与当前编号不同：旧P07对应当前P05的单星精度方向，旧P09对应当前P07的多星协同方向。历史记录中的`threshold_met=true`只表示某一开发矩阵的数值越过门限，不等于`passed=true`或当前30星多目标指标正式通过。

旧单星测试同时保留了两种Kalman基线。联邦-CI相对每个seed中最好的单模态EKF平均改善约41.93%，因此旧运行器按该口径输出`threshold_met=true`；但联邦-CI相对使用相同三模态信息的集中式EKF平均改善约-2.24%。该结果只有5个seed，输出中的`passed=false`。因此它只支持“旧单星联邦-CI优于最佳单模态EKF的开发可行性”，不支持“优于同信息Kalman”，也不支持当前P05的单观测节点CANN路径已经通过。

旧Walker-20自估计协同测试将20个节点、全部历元的位置向量误差池化为每seed全群RMSE，再计算独立绝对导航与三模态Schmidt/回放协同之间的配对改善率。20个seed、120 s结果约为1.645 m对1.467 m，逐seed改善率平均10.812%，最差seed6.735%；但正式时长要求为1200 s，因此`formal_duration_met=false`且`passed=false`。该结果属于“各卫星估计自身状态”的旧任务，不能迁移为当前“15个观测节点协同估计15个外部目标”的P07证据。

早期30星多目标矩阵还曾直接比较独立视图与共识视图的全部可用样本。以seed 0为例，独立视图只有867个位置样本、RMSE约23.915 m，共识视图有2052个样本、RMSE约15.238 m；直接计算会得到约36.28%的表面改善，但两边节点—目标—时刻集合不同。该批量测实际噪声还曾比报告协方差小约5000至8000倍。此类结果全部作废。当前P07只在共同样本上计算精度改善，并把共识新增覆盖单列为覆盖收益。

后续报告必须同时使用三个互不替代的状态字段：`threshold_met`表示开发数值门限、`formal_gates_met`表示样本量/时长/覆盖/配置冻结全部满足、`passed`仅在前两者和完整回归均为真时成立。任何摘要不得把`threshold_met`简写为“正式通过”。

## 5. 冻结的测试对象与系统边界

### 5.1 场景角色

- 总计30颗卫星：15颗我方观测星、15颗敌方目标星；
- 我方星产生光学、红外和雷达观测，并参与我方固定通信拓扑；
- 敌方目标只被观测、关联和估计，不参与我方通信，不提供自身状态；
- 第一阶段敌方目标采用非机动轨迹；机动场景作为扩展项，不阻塞当前指标关闭；
- 我方位置、速度和姿态暂按精确已知处理，但必须在最终交付前增加导航误差敏感性测试。

### 5.2 状态与坐标

正式滤波状态为J2000下六维位置—速度状态：

```text
[x, y, z, vx, vy, vz]
```

加速度根据估计状态和冻结的动力学模型解算。位置、速度、加速度分别计算误差，不得把不同单位混合成单一总RMSE。

### 5.3 通信边与观测边

- 我方—我方：通信、身份和目标级协同融合边；
- 我方—敌方：传感器观测边；
- 敌方—敌方和敌方—我方通信不进入算法输入。

CI只能融合不同我方节点对同一物理目标的估计，禁止融合不同目标的物理状态。

### 5.4 “单星”“多星”和“多目标”的冻结定义

后续代码、结果目录和报告禁止只写“单星”或“多星”而不说明视图。统一使用以下定义：

| 名称 | 本大纲中的唯一含义 | 禁止混用 |
|---|---|---|
| 单星自估计 | 一颗卫星估计自身导航/轨道状态，属于既有自估计能力 | 不作为P05对象 |
| 单观测星（P05） | 预先指定的一颗我方观测星，独立估计其实际覆盖的多个敌方目标 | 不等于单目标，也不等于15星中央汇总 |
| 多观测星独立视图 | 15颗我方星分别输出局部后验，不交换目标状态 | 不称为协同结果 |
| 多观测星协同视图（P07） | 同一批15个节点在固定拓扑内，对同一物理目标交换并融合估计 | 不允许跨目标融合 |
| 多目标 | 同时维护15个敌方目标的身份和航迹 | 与观测星数量是两个独立维度 |
| 30星场景 | 15颗我方观测星加15颗敌方目标星 | 规模打通不等于P05/P07通过 |

P05的正式配对对象固定为“同一预指定观测节点、同一目标—时刻样本”上的无CANN多模态基线和有CANN多模态候选。中央15目标汇总、最佳事后节点或不同覆盖集合均不得作为P05主比较。正式运行前必须冻结代表节点ID；若该节点只覆盖部分目标，结论只适用于该冻结覆盖集合，并必须同时报告覆盖目标数，不能外推为15/15目标全覆盖。

P07的正式配对对象固定为同一节点—目标—时刻样本上的局部独立后验和该节点接收固定拓扑协同反馈后的后验。协同新增的目标—时刻覆盖单独报告为覆盖收益，不混入6%精度改善主统计量。中央集中式结果仅保留为工程参考，不代替局部—协同配对。

## 6. 统一统计口径

### 6.1 配对原则

任何改善率或增幅都必须使用同一随机种子的配对运行。对照组与试验组必须共享：

- 敌我双方真值和初始误差；
- 原始传感器随机样本；
- 可见性、遮挡和姿态；
- 缺失窗口或节点失效窗口；
- IOD允许使用的数据；
- 评分起止时刻和目标集合。

禁止为不同算法重新生成噪声后直接比较。

### 6.2 覆盖有效性闸门

计算正式改善率前，两个配对臂必须同时满足：

1. B组、P07、R06和R08要求预期15个目标均进入评分；P05允许使用预先冻结的单节点实际覆盖集合，但必须报告覆盖目标数且不得事后选节点；
2. 配对臂的节点—目标—时间样本集合一致；P05必须保存样本键SHA-256指纹，P07必须保存共同样本数及双方独有样本数；
3. 无真值缺样；
4. 身份映射有效，身份交换单独报告；
5. 不因航迹丢失而静默删除高误差样本。

任一条件不满足时，该配对只能用于故障诊断，不能判定指标通过。

### 6.3 误差和百分比公式

对目标 `j`、时刻 `k`：

```text
e_pos(j,k) = ||r_hat(j,k) - r_true(j,k)||2
e_vel(j,k) = ||v_hat(j,k) - v_true(j,k)||2
e_acc(j,k) = ||a_hat(j,k) - a_true(j,k)||2
```

在冻结的目标—时间样本集合上分别计算位置、速度和加速度RMSE。

```text
改善率(%) = (RMSE_baseline - RMSE_candidate) / RMSE_baseline * 100
增幅(%)   = (RMSE_fault - RMSE_control) / RMSE_control * 100
```

R08若继续采用“平均误差增幅”合同口径，则使用相同样本上的误差范数均值，并在字段名中明确写为 `mean_error`，不得与RMSE混用。

### 6.4 主判据与辅助判据

- 当前位置指标作为合同主判据；
- 速度和加速度必须独立报告，不与位置混合；
- 每项同时报告全群池化值、每seed配对值、每目标值、最差目标和95%置信区间；
- 正式验收前需由项目方再次确认速度和加速度是否也必须分别满足同一百分比门限。

## 8. 正式测试矩阵

### 8.1 A组：接口、契约和不变量

验证内容：

- J2000坐标、时间戳、单位和六维状态字段；
- 三模态量测及协方差维度、正定性和坐标变换；
- 输入不携带敌方真值身份；
- `satId`、目标身份和航迹生命周期一致；
- CI不跨物理目标融合；
- 关闭CANN后严格回到无CANN路径；
- 可视化和导出为只读侧车，不改变滤波结果。

判定：全部自动化测试通过，且无NaN、Inf、非PSD协方差或时间倒退。

### 8.2 B组：30星名义端到端

链路必须包含：

```text
原始三模态数据
→ 图像/图检测和量测提取
→ 自主IOD
→ 无标签多目标关联
→ 局部多模态估计
→ 固定拓扑目标级协同
→ 身份与生命周期
→ 状态、误差和CANN输出
```

判定：15/15目标完成初始化并持续评分；身份交换、错误全局新生、意外退役均为0；所有状态和协方差有限。

### 8.3 C组：单星算法公平基线（P05）

至少运行以下配对臂：

1. 雷达单模态传统EKF；
2. 红外单模态传统EKF；
3. 光学单模态传统EKF；
4. 同信息三模态传统EKF/确定性融合，不启用CANN；
5. 待验单星多模态策略，启用CANN。

正式主比较为第5臂相对第4臂，要求位置RMSE改善不低于8%。相对最佳单模态结果作为辅助报告，不能替代同信息量多模态传统基线。

这里第4、5臂均指第5.4节定义的同一预指定单观测星视图，不使用覆盖15目标的中央聚合结果。汇总程序必须校验节点ID、样本数和节点—目标—时刻样本键SHA-256完全一致；缺少指纹或指纹不一致时只能输出诊断结果，不能输出P05通过。

CANN臂必须记录输入、解码状态、质量指标、处理动作、实际修改的量测或协方差，以及附加耗时；只生成活动图不能视为算法参与。

2026-10-20完成的L2四臂消融把雷达与两类LOS放在同一先验上做联合量测更新，解决了旧联邦-CI路径在长时运行中的seed依赖退化。项目已暂时允许“联合多模态融合+CANN”作为组合候选；该候选整体改善83.10%，达到8%门槛。但联合融合无CANN已经贡献83.03%，CANN在联合架构内仅额外贡献0.39%且95%区间跨0。因此正式表述必须是“组合候选满足P05开发门槛，主要由联合融合贡献；CANN名义精度增益尚未证实”。

单模态辅助比较也必须使用同一代表节点和共同目标—时刻样本，并逐模态分别报告。只有“候选相对预先冻结的最佳单模态”才可描述为最佳单模态改善；不得从红外或光学等较弱基线中事后挑选一个满足8%的结果。无论辅助结果如何，都不能替代第5臂相对第4臂的同信息量主比较。

### 8.4 D组：多星协同公平基线（P07）

至少运行：

1. 15个我方节点各自独立估计，不交换目标状态；
2. 15节点固定拓扑协同，不启用CANN；
3. 15节点固定拓扑协同，启用CANN。

主比较必须跨两个独立运行臂进行：基线取从未接收目标状态交换的纯独立臂局部后验，候选取固定拓扑协同臂的共识后验；二者只在共同的节点—目标—时刻键上配对，再跨15节点和15目标池化，避免事后选择最有利的单节点。预先指定的代表节点结果作为辅助报告。

不得把协同臂内部的“共识前局部状态”当作纯独立基线，因为该状态已经累积了此前历元的共识反馈。协同臂内部局部状态与本历元共识结果的0.944%平均误差改善、0.779% RMSE改善，只保留为当前历元边际融合诊断，不参与P07门限判定。

固定拓扑协同相对独立估计的位置平均误差或RMSE改善必须不低于6%；最终采用哪一种统计量必须在正式运行前与合同文字统一冻结。

### 8.5 E组：模态时段缺失（R06）

分别关闭光学、红外和雷达；其他模态继续产生真实量测并参与滤波。禁止在雷达缺失时改成只做动力学外推后宣称通过。

每次报告：

- 稳定段、缺失段和恢复段的三类RMSE；
- 缺失相对配对控制的增幅；
- 峰值、P95和最差目标；
- 恢复至控制组误差包络所需时间；
- 目标覆盖、身份交换、量测使用数和拒绝原因；
- CANN与无CANN的配对差值和耗时差值。

主判据：每种模态的位置RMSE增幅不超过15%，且覆盖有效性闸门通过。

### 8.6 F组：3/15我方节点失效（R08）

故障节点同时停止观测输出及入站、出站通信。至少覆盖四类预先冻结组合：

- 空间分散的3颗；
- 拓扑相邻的3颗；
- 对目标可见性贡献较高的3颗；
- 每seed预先生成的随机3颗。

主判据使用存活节点共识视图中的15目标全群平均误差增幅，要求不超过12%。同时报告目标级汇总、独立节点视图、最差目标、可见节点数变化、链路恢复数和恢复时间。

### 8.7 G组：身份、遮挡和成员动态

场景至少包括：

- 近距离目标交叉；
- 全节点对某目标的有限时段遮挡；
- 航迹进入COASTING/LOST后重捕获；
- 原身份创建节点退出；
- 新节点加入并继承全局身份；
- 存在在途旧消息时的节点退出。

判定：全局身份不交换、不重复新生；恢复后继承原身份；退出节点旧消息不再进入后续融合。

### 8.8 H组：实时性与状态同步延迟（P09）

必须分开测量三个量：

1. `algorithmProcessingMs`：接收完整历元输入到算法输出构造完成；
2. `stateSyncLatencyMs`：源节点完成目标报告构造，到接收节点完成反序列化、身份匹配和状态应用；
3. `frameDeadlineMiss`：完整在线服务是否超过1 s外部节拍。

100 ms合同判据只对第2项生效，除非项目方书面确认它实际指第1项。无论合同解释如何，第1项和第2项都必须报告平均、P50、P95、P99和最大值。

测试阶段：

- H1：同进程纯算法剖析；
- H2：同机跨进程、真实序列化和UDP/HTTP适配；
- H3：目标部署电脑上的单机服务；
- H4：跨设备真实网络联调，当前暂缓。

历史回放和重同步延迟单独报告，不与普通在线更新混合平均。

### 8.9 I组：长时稳定性和资源

在600 s和1200 s场景中记录：

- 每历元耗时随运行时长的趋势；
- P50/P95/P99和最坏帧；
- 进程内存、航迹数、IOD候选数和CANN流状态数；
- 消息数量、消息字节数和队列峰值；
- 身份交换、退役、新生、拒绝和协方差PSD失败；
- 结果是否随历史长度持续变慢或增长。

### 8.10 J组：30星可视化回归（F10）

设置界面至少支持双方星数与构型、固定拓扑、模态缺失、节点失效、CANN开关和算法臂选择。

展示界面至少包括：

- 我方真值、敌方真值和敌方估计；
- 我方通信边与对敌观测边；
- 15目标身份和生命周期；
- 位置、速度、加速度误差及全群RMSE；
- 选中目标的三模态原始数据和处理状态；
- 全部目标的方向环和位置热力图数据；
- CANN是否实际修改量测的动作记录。

关闭可视化前后，同一seed的算法状态、关联和指标必须一致。
