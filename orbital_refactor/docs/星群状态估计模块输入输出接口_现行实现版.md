# 星群状态估计模块输入输出接口（现行实现版）

## 1. 接口范围与总体数据流

本文只描述状态估计软件与传感器前端、协同卫星、上层应用和可视化软件
之间的外部接口，不展开 EKF、Schmidt、CI、CANN、历史回放或智能拓扑的
内部计算对象。

接口按实际数据流分为三部分：

```text
对外输入接口
├─ 初始状态与运行配置
├─ 三模态标准数值观测
└─ 三模态原始图像/矩阵
             │
             ▼
单星状态估计 ──→ 单星—多星协同衔接 ──→ 多星分布式状态估计
             │                              │
             └──────────┬───────────────────┘
                        ▼
对外输出接口
├─ 状态、协方差和融合状态
├─ 异常、运行状态和网络诊断
└─ 可视化与回放数据
```

当前滤波状态为六维 ECI 位置—速度状态：

\[
x=[x,y,z,v_x,v_y,v_z]^T。
\]

位置单位为 m，速度单位为 m/s。加速度由当前状态经二体/J2 动力学派生，
不作为独立滤波状态。

## 2. 对外输入接口

### 2.1 初始状态 `InitialState`

```text
InitialState
├─ target_id: str
├─ timestamp: float
├─ state_estimate: ndarray, shape=(6,)
└─ covariance: ndarray, shape=(6, 6)
```

| 字段 | 含义 |
|---|---|
| `target_id` | 被估计卫星或目标的唯一标识。 |
| `timestamp` | 初始状态对应时刻，单位 s。 |
| `state_estimate` | ECI 六维初始状态 `[x,y,z,vx,vy,vz]`。 |
| `covariance` | 初始状态误差协方差，描述不确定度和状态分量间相关性。 |

状态与协方差必须对应同一目标、时刻和坐标系；协方差必须为有限、对称的
半正定矩阵。

### 2.2 标准数值观测 `Observation`

`Observation` 是单星标准状态估计入口接收的量测对象。它表示已经由传感器
前端完成目标检测和物理量提取的数据，而不是完整图像。

```text
Observation
├─ timestamp: float
├─ observer_id: str
├─ target_id: str
├─ modality: str
├─ source_type: str
├─ measurement: ndarray, shape=(n_z,)
├─ covariance: ndarray, shape=(n_z, n_z)
├─ confidence: float
├─ frame: str
├─ valid_flag: bool
└─ metadata: dict[str, Any]
```

| 字段 | 含义 |
|---|---|
| `timestamp` | 物理观测形成时间；异步通信时不能用到达时间代替。 |
| `observer_id` | 产生观测的卫星或传感器节点。 |
| `target_id` | 被观测卫星或目标。 |
| `modality` | `RADAR`、`INFRARED`、`OPTICAL` 等量测模态。 |
| `source_type` | 具体数据来源，例如传统传感器、仿真前端或学习预测。 |
| `measurement` | 可直接交给对应量测模型处理的低维数值向量。 |
| `covariance` | 量测噪声协方差，维数必须与 `measurement` 一致。 |
| `confidence` | 数据源提供的 `[0,1]` 可信度摘要，不能代替协方差。 |
| `frame` | 量测参考系或表达形式，如 `SPRI`、`BODY`、`ECI`。 |
| `valid_flag` | 上游对量测是否可用的总判定。 |
| `metadata` | 姿态、量测类型、可见性原因和传感器参数等扩展信息。 |

当前三模态的正式数值量测为：

| 模态 | `measurement` | 物理含义 | 单位/表达 |
|---|---|---|---|
| 雷达 | `[rho, rho_dot]` | 两星距离和沿视线相对距离率。 | m、m/s |
| 红外 | `[azimuth, elevation]` | 目标视线的方位角和俯仰角。 | rad，星体/传感器系 |
| 光学 | `[u,v]` | 针孔相机归一化像面坐标。 | 无量纲，不是像素索引 |

红外和光学量测依赖观测星姿态。姿态应由上游姿态模块提供，或通过
`metadata` 携带约定的 ECI—星体/相机旋转信息；必要姿态缺失时量测应标为
无效。

### 2.3 原始传感器数据 `RawSensorFrame`

三种模态均已实现二维原始数据的生成、提取、记录和可视化：

| 模态 | 原始数据 | 现有具体类型 | 提取后的数值量测 |
|---|---|---|---|
| 雷达 | 距离—多普勒二维功率图 | `RadarRangeDopplerFrame.power` | `[rho,rho_dot]` |
| 红外 | 点目标、背景和噪声灰度图 | `InfraredImageFrame.image` | `[azimuth,elevation]` |
| 光学 | 点扩散目标、背景和噪声像面图 | `OpticalImageFrame.image` | `[u,v]` |

三个具体帧通过统一外部对象交换：

```text
RawSensorFrame
├─ timestamp: float
├─ observer_id: str
├─ target_id: str
├─ modality: str
├─ data: ndarray, shape=(height, width)
├─ data_kind: str
├─ axes: dict[str, ndarray]
├─ calibration: dict[str, Any]
├─ valid_flag: bool
└─ metadata: dict[str, Any]
```

| 字段 | 含义 |
|---|---|
| `data` | 原始灰度图或距离—多普勒功率矩阵。 |
| `data_kind` | 矩阵类型，用于选择正确的前端和显示方式。 |
| `axes` | 雷达的距离/距离率坐标轴，或相机的像素横纵坐标轴。 |
| `calibration` | 主点、焦距、距离分辨率、距离率分辨率等标定参数。 |
| `valid_flag` | 目标是否位于有效成像或搜索窗口内。 |
| `metadata` | 帧级扩展信息；仿真理想值只允许放在 `simulation` 子项。 |

`data_kind` 当前取值：

- `RANGE_DOPPLER_POWER_MAP`；
- `INFRARED_POINT_SOURCE_IMAGE`；
- `OPTICAL_POINT_SOURCE_IMAGE`。

原始帧不会直接放进 `ModuleInput.sensor_measurements`，处理关系为：

```text
RawSensorFrame
└─ 目标/峰值检测与质心提取
   └─ Observation 或 ObservationMessage
      └─ 状态估计
```

这种边界使滤波入口不依赖具体图像处理实现，也避免把仿真理想值误用于估计。
当前多星仿真通常只为选定链路保留完整矩阵，其他链路可直接生成数值量测以
控制开销。雷达功率图的搜索中心目前由数值量测约束，尚不是完整工程雷达
捕获链。

### 2.4 运行配置 `Config`

对外配置按用途分组：

```text
Config
├─ constellation       # 星数、轨道面、相位、高度和倾角
├─ simulation          # 时长、步长、随机种子
├─ dynamics            # 过程噪声等动力学参数
├─ measurements        # 模态开关及量测噪声
├─ visibility          # 最大距离、视场及可见性约束
├─ filter              # 滤波架构和完整性设置
├─ communication       # 时延、丢包和通信退化配置
├─ topology            # 拓扑与链路中断配置
├─ cann                # CANN 旁路开关和节点数量
└─ output              # 记录目录、自动递增和窗口开关
```

配置入口负责检查正步长、非负噪声、有效 Walker 星座划分、合法通信档位和
可写输出路径。图形化仿真配置强制使用 `schema_version="v1.0"`；普通
Python `ModuleInput.config` 为兼容旧调用允许省略版本，若提供则必须为
`v1.0`。

## 3. 单星—多星协同衔接接口

### 3.1 单星标准调用

```text
ModuleInput
├─ initial_state: InitialState
├─ sensor_measurements: list[Observation]
├─ node_reports: list[NodeReport]
└─ config: dict[str, Any]
             │
             ▼
StateAwarenessModule
             │
             ▼
ModuleOutput
```

`StateAwarenessModule` 根据配置选择现行单星联邦-CI或集中式对照算法，但
对外输入输出对象保持一致。

### 3.2 标准节点报告 `NodeReport`

```text
NodeReport
├─ node_id: str
├─ target_id: str
├─ timestamp: float
├─ state_estimate: ndarray, shape=(6,)
├─ covariance: ndarray, shape=(6, 6)
├─ quality_score: float
├─ health_status: str
├─ communication_delay: float
├─ valid_flag: bool
├─ source_timestamp: float | None
└─ arrival_timestamp: float | None
```

| 字段 | 含义 |
|---|---|
| `node_id` | 发布报告的协同节点。 |
| `target_id` | 报告所估计的物理目标；CI 只能融合对同一目标的估计。 |
| `timestamp` | 报告内状态对应时刻。 |
| `state_estimate` / `covariance` | 六维 ECI 状态与协方差。 |
| `quality_score` | 节点提供的 `[0,1]` 状态质量摘要。 |
| `health_status` | 节点健康状态。 |
| `communication_delay` | 本次传输延迟，单位 s。 |
| `valid_flag` | 报告是否可用。 |
| `source_timestamp` / `arrival_timestamp` | 报告形成时间和接收时间。 |

`node_reports` 是标准数据契约保留的节点级融合字段。当前正式单星
`StateAwarenessModule` 主链主要消费初值、数值观测和配置；现行多星 Schmidt
主链使用下面的专用网络消息，而不是依赖该字段完成协同。

### 3.3 多星网络输入集合

多星场景一次提交全网初值、拓扑和消息，最终为每颗星分别输出结果：

```text
NetworkSchmidtInput（逻辑输入集合）
├─ timestamps: ndarray
├─ initial_state_by_node: dict[node_id, ndarray]
├─ initial_covariance_by_node: dict[node_id, ndarray]
├─ topology: NetworkTopology
├─ observation_messages: list[ObservationMessage]
├─ absolute_position_observations: list[AbsolutePositionObservation]
├─ state_messages_by_receiver: dict[node_id, list[StateMessage]] | None
└─ communication / integrity / replay settings
                         │
                         ▼
run_network_schmidt_filter(...)
                         │
                         ▼
dict[node_id, NetworkModuleOutput]
```

#### 3.3.1 定向相对观测 `ObservationMessage`

```text
ObservationMessage
├─ message_id: str
├─ physical_observation_id: str | None
├─ observer_id: str
├─ target_id: str
├─ timestamp: float
├─ modality / measurement / covariance / frame
├─ confidence: float
├─ valid_flag: bool
├─ source_timestamp: float | None
├─ arrival_timestamp: float | None
└─ metadata: dict[str, Any]
```

| 字段组 | 含义 |
|---|---|
| 消息标识 | `message_id` 标识本次通信；`physical_observation_id` 在同一物理观测被转发时保持不变，防止信息重复使用。 |
| 观测方向 | `observer_id → target_id` 明确哪颗星观测了哪颗星。 |
| 量测内容 | 与 `Observation` 使用相同的三模态数值语义。 |
| 时间字段 | `timestamp` 为观测时刻，`source_timestamp` 为源端形成/发送时刻，`arrival_timestamp` 为到达时刻。 |

#### 3.3.2 绝对位置观测 `AbsolutePositionObservation`

```text
AbsolutePositionObservation
├─ timestamp: float
├─ satellite_id: str
├─ measurement_eci: ndarray, shape=(3,)
├─ covariance: ndarray, shape=(3, 3)
├─ confidence: float
├─ valid_flag: bool
├─ source_type: str
├─ observation_id: str | None
├─ arrival_timestamp: float | None
└─ metadata: dict[str, Any]
```

| 字段 | 含义 |
|---|---|
| `satellite_id` | 获得 GNSS 等绝对导航结果的卫星。 |
| `measurement_eci` | ECI 绝对位置 `[x,y,z]`，单位 m。 |
| `covariance` | 三维绝对位置协方差。 |
| `observation_id` | 物理观测唯一标识，用于重复信息识别。 |
| `arrival_timestamp` | 绝对导航数据抵达估计节点的时间。 |
| 其他字段 | 数据源、可信度、有效性和扩展信息。 |

它的作用是为指定卫星提供绝对位置锚点，抑制仅依靠相对量测时的整体漂移。
它是多星网络入口的独立输入，不是 `ModuleInput` 的直接字段。

#### 3.3.3 邻星状态消息 `StateMessage`

```text
StateMessage
├─ source_node_id: str
├─ target_node_id: str
├─ timestamp: float
├─ state_estimate: ndarray, shape=(6,)
├─ covariance: ndarray, shape=(6, 6)
├─ quality_score: float
├─ valid_flag: bool
├─ source_timestamp: float | None
├─ arrival_timestamp: float | None
└─ metadata: dict[str, Any]
```

| 字段 | 含义 |
|---|---|
| `source_node_id` | 发送状态估计的邻星。 |
| `target_node_id` | 状态消息所描述的物理卫星。 |
| `timestamp` | 状态估计对应的参考时刻。 |
| `state_estimate` / `covariance` | 六维 ECI 状态与协方差。 |
| `quality_score` / `valid_flag` | 状态质量摘要与总有效标志。 |
| `source_timestamp` / `arrival_timestamp` | 形成/发送时间和接收时间，用于识别延迟与乱序。 |
| `metadata` | 链路、版本和扩展诊断信息。 |

现行对象还携带精确协方差传输与来源跟踪所需字段；这些属于协同算法内部
协议，不在对外接口文档中展开。

### 3.4 从单星到多星的对应关系

| 单星概念 | 多星扩展 | 关系 |
|---|---|---|
| 一份 `InitialState` | `initial_state_by_node` | 为每颗星分别初始化，不合并不同卫星的状态。 |
| `Observation` | `ObservationMessage` | 增加明确观测方向、物理信息标识和通信时间。 |
| 绝对位置数值量测 | `AbsolutePositionObservation` | 明确锚点属于哪颗星并支持异步到达。 |
| `NodeReport` | `StateMessage` | 从标准节点报告扩展为支持异步、来源跟踪和协方差传输的网络消息。 |
| `ModuleOutput` | `NetworkModuleOutput` | 每颗星仍输出标准结果，另外附加网络诊断。 |

CI 只用于融合“对同一物理目标的多份相关估计”，不会把不同卫星的物理状态
直接合并为一个状态。

## 4. 对外输出接口

### 4.1 标准输出 `ModuleOutput`

```text
ModuleOutput
├─ state_output: StateOutput
├─ fusion_status: FusionStatus
├─ abnormal_events: list[AbnormalEvent]
└─ runtime_status: RuntimeStatus
```

#### 4.1.1 状态估计 `StateOutput`

```text
StateOutput
├─ timestamp: float
├─ target_id: str
├─ position_estimate: ndarray, shape=(3,)
├─ velocity_estimate: ndarray, shape=(3,)
├─ acceleration_estimate: ndarray, shape=(3,)
├─ covariance: ndarray, shape=(6, 6)
├─ valid_flag: bool
└─ confidence_level: float
```

| 字段 | 含义 |
|---|---|
| `timestamp` | 输出状态对应时刻。 |
| `target_id` | 被估计目标；多星场景为每颗星分别输出。 |
| `position_estimate` | ECI 位置估计，单位 m。 |
| `velocity_estimate` | ECI 速度估计，单位 m/s。 |
| `acceleration_estimate` | 由状态和动力学派生的 ECI 加速度，单位 m/s²。 |
| `covariance` | 六维位置—速度状态协方差。 |
| `valid_flag` | 当前结果是否满足输出条件。 |
| `confidence_level` | 面向上层的可信度摘要；完整不确定度仍以协方差为准。 |

#### 4.1.2 融合状态 `FusionStatus`

```text
FusionStatus
├─ modality_weights: dict[str, float]
├─ modality_valid_flags: dict[str, bool]
├─ node_weights: dict[str, float]
├─ active_nodes: list[str]
└─ lost_nodes: list[str]
```

| 字段 | 含义 |
|---|---|
| `modality_weights` | 单星多模态局部估计的融合权重。 |
| `modality_valid_flags` | 各模态在本次输出时是否有效。 |
| `node_weights` | 对同一目标进行节点级融合时使用的权重。 |
| `active_nodes` | 当前参与估计或融合的节点。 |
| `lost_nodes` | 因失联、故障或有效性检查未参与的节点。 |

#### 4.1.3 异常事件 `AbnormalEvent`

```text
AbnormalEvent
├─ timestamp: float
├─ event_type: str
├─ severity: str
├─ description: str
├─ node_id: str | None
├─ target_id: str | None
└─ modality: str | None
```

| 字段 | 含义 |
|---|---|
| `event_type` | 量测拒绝、节点失联、重新同步等事件类别。 |
| `severity` | `INFO`、`WARNING` 或 `ERROR`。 |
| `description` | 面向操作人员的事件说明。 |
| 其他字段 | 事件时间及相关节点、目标和模态；不适用时为空。 |

#### 4.1.4 运行状态 `RuntimeStatus`

```text
RuntimeStatus
├─ processing_time: float
├─ observation_count: int
├─ active_modality_count: int
├─ active_node_count: int
└─ status: str
```

| 字段 | 含义 |
|---|---|
| `processing_time` | 本次处理耗时，单位 s。 |
| `observation_count` | 本次接收或处理的观测数。 |
| `active_modality_count` | 至少提供一条有效信息的模态数。 |
| `active_node_count` | 本次参与处理的节点数。 |
| `status` | `OK`、`DEGRADED`、`PREDICTION_ONLY` 或 `FAILED`。 |

### 4.2 多星输出 `NetworkModuleOutput`

```text
NetworkModuleOutput
├─ module_output: ModuleOutput
└─ network_diagnostics: NetworkRuntimeDiagnostics
```

每颗卫星均保留标准 `ModuleOutput`，同时附加网络诊断。诊断回答当前使用哪版
拓扑、哪些邻星有效、是否丢包或等待重同步，以及异步处理资源是否超限；它
不会作为新的观测反向修改状态结果。

```text
NetworkRuntimeDiagnostics
├─ node_id: str
├─ configured_neighbors / active_neighbors / inactive_configured_neighbors
├─ current_topology_version / topology_transition_count
├─ link_health_by_neighbor
├─ last_receive_timestamp_by_neighbor
├─ losses_before_last_delivery_by_neighbor
├─ maximum_consecutive_losses_by_neighbor
├─ recovery_delivery_count_by_neighbor
├─ resynchronization_required_by_neighbor
├─ message_rejection_counts_by_reason
├─ replay_count / replay_batch_count / replay_fallback_count
├─ maximum_replay_seconds
├─ maximum_retained_journal_count
├─ maximum_checkpoint_count
├─ maximum_pinned_checkpoint_count
└─ maximum_resync_required_count
```

| 字段组 | 含义 |
|---|---|
| 邻居集合 | 区分配置邻居、当前有效邻居和当前失效邻居。 |
| 拓扑版本 | 当前拓扑版本及运行期间切换次数。 |
| 链路状态 | 各邻星最后接收时间、最近交付前丢包数和最大连续丢包数。 |
| 恢复与同步 | 链路恢复交付次数及当前是否等待重新同步。 |
| 拒绝统计 | 按具体原因汇总被拒绝的消息。 |
| 异步处理 | 回放、批量回放、回退次数和最长处理时间。 |
| 资源峰值 | 历史日志、检查点、钉住检查点和待同步数量峰值。 |

### 4.3 可视化与回放输出 `VisualizationFrame`

`VisualizationFrame` 是可选的只读展示接口，不是滤波器正式状态输出。关闭
记录或窗口不会改变滤波结果。

```text
VisualizationFrame
├─ scenario_id / run_id
├─ timestamp / epoch_index
├─ nodes: list[VisualNodeState]
├─ edges: list[VisualEdge]
├─ observations: list[VisualObservation]
├─ navigation: list[VisualNavigationState]
├─ cann: list[VisualCANNSnapshot]
├─ events: list[VisualDiagnosticEvent]
├─ schema_version: str
└─ metadata: dict[str, Any]
```

| 字段 | 含义 |
|---|---|
| `nodes` | 各星估计状态、协方差摘要及仅供仿真显示的真值。 |
| `edges` | 配置拓扑、活动链路和观测/信息流关系。 |
| `observations` | 数值观测、可见性、有效性、NIS 及可选原始图像。 |
| `navigation` | 绝对导航可用性、最后有效时刻、锚点年龄和 RT 导航量。 |
| `cann` | Ring、Line 和位置细胞活动及解码摘要。 |
| `events` | 窗口显示的异常和状态变化。 |
| `schema_version` | 回放帧格式版本，当前为 `v1.0`。 |

单条观测中的 `raw_sensor_data` 保存二维图像/功率图，`raw_data_kind` 标识
矩阵类型。大型数组写入 `arrays/*.npz`，帧 JSON 只保存引用。

```text
VisualizationRecording
├─ manifest.json
├─ frames/*.json
└─ arrays/*.npz
```

## 5. 数据格式、单位与版本约定

### 5.1 单位与坐标系

| 数据 | 单位或表达 |
|---|---|
| ECI 位置 | m |
| ECI 速度 | m/s |
| 派生加速度 | m/s² |
| 雷达距离 / 距离率 | m / m/s |
| 方位角 / 俯仰角 | rad |
| 光学 `[u,v]` | 归一化像面坐标，无量纲 |
| 相机原始矩阵坐标轴 | pixel |
| 时间戳和通信延迟 | s |

### 5.2 枚举、校验和错误码

现行代码集中定义了模态、参考系、运行状态、严重度和机器可读接口错误码。
`StateAwarenessModule` 入口检查：

- 标识和时间戳；
- 状态及量测维数；
- 数值有限性；
- 协方差形状、对称性和半正定性；
- 模态与参考系兼容性；
- 可信度和节点报告目标一致性。

### 5.3 文件交换格式

```text
RawSensorFrameRecording
├─ raw_sensor_frame.json
└─ arrays.npz
```

该格式不使用 pickle。JSON 保存版本、标识、类型、标定和数组引用，NPZ 保存
二维矩阵、坐标轴和元数据数组；读取时校验 `v1.0`、数组键、数据类型、形状
和完整接口约束。已有目录默认不覆盖。
