# 星群状态估计模块输入输出接口（现行实现版）

## 1. 范围与约定

本文仅描述软件模块的对外输入、输出和可选可视化记录，不展开 EKF、Schmidt、CI、CANN、历史回放或拓扑策略的内部数据结构。

当前滤波状态为六维 ECI 位置—速度状态：

\[
x=[x,y,z,v_x,v_y,v_z]^T
\]

位置单位为 m，速度单位为 m/s。加速度由当前状态经二体/J2 动力学派生，不是独立滤波状态。

---

## 2. 总体接口

### 2.1 输入

```text
ModuleInput
├─ initial_state: InitialState
├─ sensor_measurements: list[Observation]
├─ node_reports: list[NodeReport]
└─ config: dict[str, Any]
```

| 字段 | 含义 |
|---|---|
| `initial_state` | 待估目标的初始状态及其不确定度。 |
| `sensor_measurements` | 当前批次的绝对导航或星间多模态观测。 |
| `node_reports` | 多星协同时其他节点对同一目标给出的状态报告；单星运行可为空。 |
| `config` | 星座、仿真、量测、通信、CANN 和输出配置。 |

### 2.2 输出

```text
ModuleOutput
├─ state_output: StateOutput
├─ fusion_status: FusionStatus
├─ abnormal_events: list[AbnormalEvent]
└─ runtime_status: RuntimeStatus

NetworkModuleOutput                 # 多星运行补充
├─ module_output: ModuleOutput
└─ network_diagnostics: NetworkRuntimeDiagnostics

VisualizationRecording             # 可选回放输出
├─ manifest.json
├─ frames/*.json
└─ arrays/*.npz

RawSensorFrameRecording            # 单帧原始数据交换
├─ raw_sensor_frame.json
└─ arrays.npz
```

## 3. 对外输入接口

### 3.1 初始状态 `InitialState`

```text
InitialState
├─ target_id: str
├─ timestamp: float
├─ state_estimate: ndarray, shape=(6,)
└─ covariance: ndarray, shape=(6, 6)
```

| 字段 | 含义 |
|---|---|
| `target_id` | 被估计卫星或目标的唯一标识。 |
| `timestamp` | 初始状态对应的时间，单位 s。 |
| `state_estimate` | ECI 六维初始状态 `[x,y,z,vx,vy,vz]`。 |
| `covariance` | 初始状态误差协方差，描述不确定度及状态分量间相关性。 |

状态和协方差必须对应同一目标、同一时刻和同一坐标系；协方差应为有限、对称的半正定矩阵。

### 3.2 标准观测 `Observation`

```text
Observation
├─ timestamp: float
├─ observer_id: str
├─ target_id: str
├─ modality: str
├─ source_type: str
├─ measurement: ndarray, shape=(n_z,)
├─ covariance: ndarray, shape=(n_z, n_z)
├─ confidence: float
├─ frame: str
├─ valid_flag: bool
└─ metadata: dict[str, Any]
```

| 字段 | 含义 |
|---|---|
| `timestamp` | 观测形成时间，单位 s；异步通信时不能用到达时间代替。 |
| `observer_id` | 产生观测的卫星或传感器节点。 |
| `target_id` | 被观测目标；绝对导航时通常与 `observer_id` 相同。 |
| `modality` | 模态，例如 `RADAR`、`INFRARED`、`OPTICAL`、`ABSOLUTE_POSITION`。 |
| `source_type` | 数据来源或具体传感器类型，例如 `GNSS`、`SIMULATED_RADAR`。 |
| `measurement` | 从传感器数据提取、可供量测模型直接使用的数值向量。 |
| `covariance` | 量测噪声协方差，维数须与 `measurement` 一致。 |
| `confidence` | 数据源提供的归一化可信度；不能代替协方差。 |
| `frame` | 量测参考系或表达方式，例如 `ECI`、`BODY_AZ_EL`。 |
| `valid_flag` | 上游对该观测是否可用的总判定。 |
| `metadata` | 姿态、传感器参数、可见性原因、原始数据引用等扩展信息。 |

#### 当前各模态的标准量测

| 模态 | `measurement` | 含义 | 参考系/表达 |
|---|---|---|---|
| 雷达 | `[rho, rho_dot]` | 两星距离 m、沿视线相对距离率 m/s。 | 相对 ECI 几何 |
| 红外 | `[azimuth, elevation]` | 目标视线在星体/传感器系中的方位角、俯仰角，单位 rad。 | `BODY_AZ_EL` |
| 光学 | `[u, v]` | 针孔相机归一化像面坐标，不是像素索引。 | `CAMERA_NORMALIZED` |
| 绝对导航 | `[x, y, z]` | 本星 ECI 绝对位置，单位 m。 | `ECI` |

红外与光学量测依赖观测星姿态。姿态应由上游姿态模块提供，或以约定的旋转信息写入 `metadata`；缺少必要姿态信息时应将观测标为无效。

### 3.3 绝对位置观测 `AbsolutePositionObservation`

```text
AbsolutePositionObservation
├─ timestamp: float
├─ satellite_id: str
├─ measurement_eci: ndarray, shape=(3,)
├─ covariance: ndarray, shape=(3, 3)
├─ confidence: float
├─ valid_flag: bool
├─ source_type: str
├─ observation_id: str | None
├─ arrival_timestamp: float | None
└─ metadata: dict[str, Any]
```

| 字段 | 含义 |
|---|---|
| `satellite_id` | 获得绝对导航结果的卫星。 |
| `measurement_eci` | ECI 绝对位置 `[x,y,z]`，单位 m。 |
| `observation_id` | 观测唯一标识，用于识别重复数据；可自动生成。 |
| `arrival_timestamp` | 数据抵达估计节点的时刻，与量测形成时间分开保存。 |
| 其他同名字段 | 与 `Observation` 中的含义一致。 |

### 3.4 多星节点报告 `NodeReport`

```text
NodeReport
├─ node_id: str
├─ target_id: str
├─ timestamp: float
├─ source_timestamp: float | None
├─ arrival_timestamp: float | None
├─ state_estimate: ndarray, shape=(6,)
├─ covariance: ndarray, shape=(6, 6)
├─ quality_score: float
├─ health_status: str
├─ communication_delay: float
└─ valid_flag: bool
```

| 字段 | 含义 |
|---|---|
| `node_id` | 发布状态报告的协同节点。 |
| `target_id` | 报告所估计的物理目标；只有同一目标的多份估计才可进入 CI。 |
| `timestamp` | 报告内状态对应的参考时刻。 |
| `source_timestamp` | 报告在源节点形成的时刻。 |
| `arrival_timestamp` | 报告到达接收节点的时刻。 |
| `state_estimate` | 源节点提供的六维 ECI 状态估计。 |
| `covariance` | 与该状态对应的协方差。 |
| `quality_score` | 源节点给出的状态质量评分。 |
| `health_status` | 节点健康状态，例如 `OK`、`DEGRADED`、`FAULT`。 |
| `communication_delay` | 本次传输延迟，单位 s。 |
| `valid_flag` | 报告能否进入协同处理的总标志。 |

### 3.5 三模态原始图像/矩阵

三种模态均已实现二维原始数据的生成、提取、记录和可视化。滤波器的正式输入仍是从二维数据提取出的低维 `Observation.measurement`：

```text
原始图像或功率矩阵
└─ 峰值/目标检测与质心提取
   └─ 标准 Observation
      └─ 状态估计模块
```

| 模态 | 已实现的二维数据 | 现行对象字段 | 提取结果 |
|---|---|---|---|
| 雷达 | 距离—多普勒功率图 | `RadarRangeDopplerFrame.power` | `[rho, rho_dot]` |
| 红外 | 点目标、背景和噪声灰度图 | `InfraredImageFrame.image` | `[azimuth, elevation]` |
| 光学 | 点扩散目标、背景和噪声像面图 | `OpticalImageFrame.image` | 归一化 `[u,v]` |

三个具体帧现已通过统一的外部 `RawSensorFrame` 携带；原具体类型仍保留并具有双向适配器：

```text
RawSensorFrame
├─ timestamp: float
├─ observer_id: str
├─ target_id: str
├─ modality: str
├─ data: ndarray, shape=(height, width)
├─ data_kind: str
├─ axes: dict[str, ndarray]
├─ calibration: dict[str, Any]
├─ valid_flag: bool
└─ metadata: dict[str, Any]
```

`axes` 为雷达保存距离/距离率坐标轴，为相机保存像素坐标轴；`calibration` 保存分辨率、主点和焦距等解释矩阵所需的标定参数。仿真专有的理想值只存放在 `metadata["simulation"]` 中，不属于真实设备必需输入，也不得进入正式估计链路。

可视化接口再通过下列字段携带完整矩阵：

```text
VisualObservation
├─ raw_sensor_data: ndarray | None
└─ raw_data_kind: str | None
```

`raw_data_kind` 当前包括：

- `RANGE_DOPPLER_POWER_MAP`：雷达距离—多普勒功率图；
- `INFRARED_POINT_SOURCE_IMAGE`：红外点目标图；
- `OPTICAL_POINT_SOURCE_IMAGE`：光学点目标图。

当前边界是：原始图像前端已经贯通，但多星仿真通常只为选定链路保存完整矩阵，其余链路可直接生成数值量测以控制开销；雷达功率图的搜索中心目前由数值量测约束，尚不是完整工程雷达捕获链。

### 3.6 配置 `config`

```text
Config
├─ constellation
│  ├─ total_satellites
│  ├─ plane_count
│  ├─ phasing
│  ├─ altitude_km
│  └─ inclination_deg
├─ simulation
│  ├─ duration_s
│  ├─ dt_s
│  ├─ seed
│  └─ process_noise_acceleration
├─ measurements_visibility
│  ├─ radar_enabled / infrared_enabled / optical_enabled
│  ├─ radar_range_sigma_m
│  ├─ radar_range_rate_sigma_mps
│  ├─ infrared_angle_sigma_deg
│  ├─ optical_image_sigma
│  ├─ absolute_navigation_sigma_m
│  ├─ maximum_range_km
│  └─ enable_absolute_navigation_dropout
├─ communication_topology
│  ├─ communication_profile
│  └─ enable_link_suspension
├─ cann
│  ├─ cann_enabled
│  └─ cann_node_limit
└─ output
   ├─ output
   ├─ open_after_run
   └─ auto_increment_output
```

| 分组 | 含义 |
|---|---|
| `constellation` | Walker 星座规模、轨道面、相位、轨道高度和倾角。 |
| `simulation` | 仿真时长、离散步长、随机种子和过程噪声。 |
| `measurements_visibility` | 三模态开关、量测噪声、最大可见距离及绝对导航中断。 |
| `communication_topology` | 通信时延/丢包档位与链路中断开关。 |
| `cann` | 是否生成 CANN 旁路导航结果及最多处理节点数；它不改变原状态定义。 |
| `output` | 记录路径、结束后是否打开窗口、路径重名时是否自动递增。 |

运行前应检查正步长、非负噪声、有效星座划分和可写输出路径。

## 4. 对外输出接口

### 4.1 状态结果 `StateOutput`

```text
StateOutput
├─ timestamp: float
├─ target_id: str
├─ position_estimate: ndarray, shape=(3,)
├─ velocity_estimate: ndarray, shape=(3,)
├─ acceleration_estimate: ndarray, shape=(3,)
├─ covariance: ndarray, shape=(6, 6)
├─ valid_flag: bool
└─ confidence_level: float
```

| 字段 | 含义 |
|---|---|
| `timestamp` | 输出状态的参考时刻。 |
| `target_id` | 被估计目标；多星场景为每颗星分别输出。 |
| `position_estimate` | ECI 位置估计，单位 m。 |
| `velocity_estimate` | ECI 速度估计，单位 m/s。 |
| `acceleration_estimate` | 由状态和动力学派生的 ECI 加速度，单位 m/s²。 |
| `covariance` | 六维位置—速度状态协方差。 |
| `valid_flag` | 结果是否满足输出条件。 |
| `confidence_level` | 面向上层的归一化可信度摘要；完整不确定度以协方差为准。 |

### 4.2 融合状态 `FusionStatus`

```text
FusionStatus
├─ modality_weights: dict[str, float]
├─ modality_valid_flags: dict[str, bool]
├─ node_weights: dict[str, float]
├─ active_nodes: list[str]
└─ lost_nodes: list[str]
```

| 字段 | 含义 |
|---|---|
| `modality_weights` | 单星多模态局部估计的融合权重。 |
| `modality_valid_flags` | 各模态在本次输出时是否有效。 |
| `node_weights` | 对同一物理目标进行节点级融合时使用的权重。 |
| `active_nodes` | 当前参与估计或融合的节点。 |
| `lost_nodes` | 因失联、故障或有效性检查未参与的节点。 |

CI 只融合对同一物理目标的相关估计，不把不同卫星的物理状态直接合为一个状态。

### 4.3 异常事件 `AbnormalEvent`

```text
AbnormalEvent
├─ timestamp: float
├─ event_type: str
├─ severity: str
├─ description: str
├─ node_id: str | None
├─ target_id: str | None
└─ modality: str | None
```

| 字段 | 含义 |
|---|---|
| `timestamp` | 事件发生或被检测到的时间。 |
| `event_type` | 事件类别，如量测拒绝、节点失联或重新同步。 |
| `severity` | 严重程度，如 `INFO`、`WARNING`、`ERROR`。 |
| `description` | 面向操作人员的事件说明。 |
| `node_id` / `target_id` / `modality` | 相关节点、目标和模态；不适用时为空。 |

### 4.4 运行状态 `RuntimeStatus`

```text
RuntimeStatus
├─ processing_time: float
├─ observation_count: int
├─ active_modality_count: int
├─ active_node_count: int
└─ status: str
```

| 字段 | 含义 |
|---|---|
| `processing_time` | 本次处理耗时，单位 s。 |
| `observation_count` | 本次接收或处理的观测数。 |
| `active_modality_count` | 至少提供一条有效信息的模态数。 |
| `active_node_count` | 本次参与处理的节点数。 |
| `status` | 总体状态，如 `OK`、`DEGRADED`、`FAILED`。 |


| 字段组 | 含义 |
|---|---|

### 4.6 可视化回放 `VisualizationFrame`

```text
VisualizationFrame
├─ scenario_id: str
├─ run_id: str
├─ timestamp: float
├─ epoch_index: int
├─ nodes: list[VisualNodeState]
├─ edges: list[VisualEdge]
├─ observations: list[VisualObservation]
├─ navigation: list[VisualNavigationState]
├─ cann: list[VisualCANNSnapshot]
├─ events: list[VisualDiagnosticEvent]
├─ schema_version: str
└─ metadata: dict[str, Any]
```

| 字段 | 含义 |
|---|---|
| `nodes` | 各星真值（仅仿真可选）、估计状态、协方差摘要和有效状态。 |
| `edges` | 配置拓扑、活动链路及观测/信息流关系。 |
| `observations` | 数值量测、可见性、有效性、NIS 及可选原始图像/矩阵。 |
| `navigation` | 绝对导航可用性、最后有效时刻、锚点年龄和 RT 导航量。 |
| `cann` | Ring、Line 和位置细胞活动及解码摘要。 |
| `events` | 窗口事件列表所需的异常和状态变化。 |
| `schema_version` | 回放格式版本，当前为 `v1.0`。 |

单条可视化观测为：

```text
VisualObservation
├─ observer_id: str
├─ target_id: str
├─ modality: str
├─ measurement: ndarray
├─ covariance_diagonal: ndarray
├─ visible: bool
├─ valid: bool
├─ processing_status: str
├─ frame: str
├─ nis: float | None
├─ raw_sensor_data: ndarray | None
├─ raw_data_kind: str | None
└─ metadata: dict[str, Any]
```

大型数组保存在 `arrays/*.npz`，帧 JSON 只保存引用，避免重复编码完整图像。

单个 `RawSensorFrame` 也可独立保存为 `raw_sensor_frame.json + arrays.npz`。该格式不使用 pickle，JSON 保存标识、类型、标定和数组引用，NPZ 保存原始矩阵、坐标轴及元数据中的数组；读取时会校验 `v1.0` 版本、数组键、数据类型、形状和完整接口约束。

## 5. 当前接口边界与后续规范化

当前代码已具备上述核心数据类、三模态数值量测、三模态二维数据前端、多星诊断和可视化回放。正式交付前建议继续统一：

1. `modality`、`frame`、运行状态、严重度和接口错误码已经集中定义为字符串兼容枚举；
2. 正式入口已经校验状态、量测和协方差的维数、有限性、对称性、半正定性，以及模态—坐标系组合；
3. 通用模块配置支持可选 `schema_version="v1.0"`，图形化仿真配置已经强制使用 `v1.0` 并执行分组字段校验；
4. 三个具体原始帧已经统一封装为正式 `RawSensorFrame`，并保留与旧类型的兼容适配；
5. 隔离仿真真值与实装数据，正式设备接口不得依赖真值；
6. 时间戳、目标标识、维数、协方差和坐标系不一致已经具有统一机器可读错误码；后续可再冻结跨进程传输格式。

这些规范化工作不会改变现有滤波、CI、Schmidt、CANN 或拓扑算法，只用于稳定模块边界并方便系统联调与验收。
